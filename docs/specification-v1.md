# UBCM v1: нормативная спецификация

Этот документ фиксирует бинарные форматы, адресацию и семантику исполнения UBCM версии 1. Термины `MUST`, `MUST NOT` и «ошибка» являются нормативными требованиями.

## 1. Модель выполнения

Процедура — неизменяемый битовый вектор. Распознающая сеть (РС) — изменяемый граф узлов, хранящийся в регистрах. Исполняемая программа определяется парой «процедура + РС».

Активация содержит позицию в процедуре, ссылку на состояние текущей РС, локальный резолвер, ссылку на вызывающую активацию, регистр результата и состояние префикса. VM выполняет один текущий узел за шаг.

Поле `DATA` узла выбирает встроенную команду VM. Имя команды не дублируется в процедуре: процедура содержит только аргументы. Например, при `DATA=0100` VM читает из процедуры пятибитный код вычислительной операции, источники, приёмник и бит ветвления.

## 2. Порядок битов и ошибки

- Потоки в регистрах и файлах используют Big-Endian.
- Байты идут от старшего к младшему; внутри байта первым читается бит 7.
- Битовый адрес 0 указывает на бит 7 первого байта.
- Многобайтовые поля записываются в сетевом порядке.
- Адреса и размеры являются беззнаковыми 64-битными значениями.
- Зарезервированные и дополняющие биты обязаны быть нулевыми.
- Выход за границу, переполнение адреса, неверная ссылка и нарушение формата дают структурированную ошибку VM. Неопределённое поведение и аварийное завершение процесса недопустимы.

## 3. Базовые кодеки

```text
Size      := byte_count_minus_1:3 | value:(byte_count * 8)
BitString := bit_count:Size | data:bit_count
VarUInt   := bit_count:Size | unsigned_value:bit_count
VarInt    := bit_count:Size | twos_complement_value:bit_count
Name      := BitString
```

В `Size` код `000` задаёт один байт значения, `111` — восемь. Кодирование обязано использовать минимальное число байтов.

`VarUInt` использует минимальную битовую ширину. Ширина 0 кодирует ноль и не содержит данных. `VarInt` использует минимальное дополнительное представление шириной от 0 до 64 бит.

Вещественные числа:

```text
VarFloat := mantissa:VarInt | exponent:VarInt
value    := mantissa * 2^exponent

Value    := 0 | VarUInt
          | 1 | VarFloat
```

Для вычислений `VarFloat` преобразуется в IEEE-754 `double`. Конечный результат преобразуется через `frexp` в целую мантиссу точностью не более 53 значащих бит и двоичный порядок. Ноль — нулевые мантисса и порядок. `NaN` и бесконечность не сериализуются.

Для канонического хранения ненулевой мантисса должна быть нечётной; степени двойки выносятся из мантиссы в порядок. Ненормализованная пара при декодировании отвергается.

Битовые строки произвольной длины разрешены, но вычисляемое целое не может быть шире 64 бит. Отрицательное число — знаковая интерпретация тех же битов в дополнительном коде.

## 4. Регистры и имена

Имя имеет длиновую оболочку `Name`; его биты интерпретирует соответствующая РС-резолвер. Резолвер возвращает стабильный идентификатор регистра.

```text
RegisterHandle := class:2 | id:62
```

Классы:

| Код | Класс |
|---|---|
| `00` | тело текущей процедуры, `id=0` |
| `01` | сверхлокальный регистр |
| `10` | локальный регистр |
| `11` | глобальный регистр |

Идентификатор удалённого регистра не переиспользуется до завершения VM.

В процедуре регистр выбирается так:

```text
RegisterSelector := 00
                  | class:2 | Name       ; class != 00

RegisterAddress := RegisterSelector | offset:Size
```

## 5. Адресация

```text
Reference := 00 | immediate:VarUInt
           | 01 | pointer_location:RegisterAddress
           | 10 | target:RegisterAddress
           | 11 | depth:Size | indirect:1 | local_name:Name | offset:Size

Source      := 00 | immediate:VarUInt
             | Reference | bit_count:Size       ; mode != 00

Destination := Reference                        ; mode 00 forbidden
```

- `00` — непосредственное беззнаковое целое.
- `01` — адрес места, где записана следующая самодостаточная `Reference`.
- `10` — прямой адрес.
- `11` — локальный регистр другой активации. Глубина 0 означает текущую, 1 — предыдущую. `indirect=1` означает, что по указанному адресу находится следующая `Reference`.

Косвенные ссылки разрешаются рекурсивно. Стандартный предел — 64 уровня; превышение, в том числе из-за цикла, является ошибкой.

Источник возвращает ровно `bit_count` бит. Доступный диапазон приёмника — суффикс регистра от разрешённого адреса до конца. Значение записывается в начало диапазона, оставшийся хвост обнуляется. Если значение не помещается, состояние не изменяется.

Копирование трактует источник как необработанную строку. Числовые команды требуют корректный `Value`; оставшаяся часть диапазона источника может содержать только нули. Запись в процедуру запрещена. Все проверки команды завершаются до первого изменения состояния.

## 6. Узлы распознающей сети

```text
NodeRef := register:RegisterHandle | bit_offset:u64_be
```

`NodeRef` занимает 128 бит. Нулевая ссылка — 128 единичных бит. Значение зарезервировано и не может обозначать настоящий объект.

Узел имеет фиксированный размер 592 бита (74 байта):

```text
TYPE:1 | DATA:15 | ACTION:192 |
next0:NodeRef | next1:NodeRef | superlocal_resolver:NodeRef
```

При `TYPE=0` младшие четыре бита `DATA` содержат имя команды `0000..1101`; старшие 11 бит и `ACTION` равны нулю.

При `TYPE=1` поле `DATA` равно нулю, а `ACTION` содержит:

```text
procedure:RegisterHandle | entry:NodeRef
```

Такой узел вызывает пользовательскую процедуру. Узлы начинаются по битовым адресам, кратным 592. Активную РС разрешено изменять; узел каждый раз читается из актуальных битов без невалидного кэша.

## 7. Активации

Ссылки на активацию и ячейку состояния сети имеют формат `RegisterHandle | u64_be` длиной 128 бит. Ячейка сети содержит один `NodeRef`.

Активационная запись фиксирована: 744 бита (93 байта).

```text
magic:16 = 0x5541 | version:8 = 1 | flags:8 |
procedure:RegisterHandle | procedure_position:u64_be |
network_state_ref:128 | local_resolver:NodeRef |
prev_activation_ref:128 | result_register:RegisterHandle |
prefix_kind:8 | prefix_payload:128
```

`prefix_kind`: 0 — нет, 1 — чтение, 2 — изменение, 3 — условие. Для чтения и изменения младшие 64 бита payload содержат глубину; для условия младший бит содержит вычисленное логическое значение. Прочие биты нулевые.

Регистр результата создаётся вместе с активацией как служебный локальный регистр с зарезервированным пустым именем и удаляется вместе с ней.

`0110` разделяет `network_state_ref` с вызывающей активацией. `0111` и `1000` создают новую ячейку состояния с новой точкой входа.

## 8. Один шаг VM

1. Получить текущую активацию и заново декодировать её текущий узел.
2. Для `TYPE=0` выбрать формат команды по `DATA`.
3. Полностью декодировать аргументы и один бит ветвления из выбранного потока чтения.
4. Проверить границы, ссылки, типы и ограничения без изменения состояния.
5. Выполнить эффект и записать `next0` или `next1` в выбранную ячейку состояния.

Вызов сначала устанавливает продолжение вызывающей активации, затем создаёт новую. `1011` не читает бит ветвления и удаляет текущую активацию. Если она корневая, VM нормально завершается.

Для `TYPE=1` VM записывает вызывающей активации `next0`, не читает бит и создаёт активацию из `ACTION`.

`0011` не читает дополнительный бит: общий этап ветвления является всем эффектом этой команды.

## 9. Префиксы

- Префикс применяется ровно к следующей распознанной встроенной команде и затем сбрасывается.
- Комбинировать префиксы запрещено; второй активный префикс — ошибка.
- Префикс чтения выбирает процедуру активации, из которой читаются аргументы и бит ветвления. Текущий узел остаётся узлом текущей активации.
- Префикс изменения перенаправляет локальные/сверхлокальные записи, изменение позиции и переход узла на выбранную активацию. Для `0110`, `0111`, `1000`, `1011` глубина обязана быть нулевой.
- Условие вычисляется при выполнении префикса. При лжи следующая команда синтаксически декодируется и потребляет бит ветвления, но её основной эффект подавляется; переход РС выполняется.

## 10. Встроенные команды

| `DATA` | Аргументы в процедуре | Эффект |
|---|---|---|
| `0000` | `depth:Size` | префикс чтения |
| `0001` | `depth:Size` | префикс изменения |
| `0010` | `condition:Destination` | условный префикс |
| `0011` | — | чистое ветвление |
| `0100` | `operation:5`, один/два `Source`, `Destination` | вычисление |
| `0101` | `Source`, `Destination` | копирование |
| `0110` | `Source(procedure register)` | новая процедура, та же РС |
| `0111` | `Source(NodeRef)` | та же процедура, новая РС |
| `1000` | `Source(procedure bits)`, `Source(NodeRef)` | новая процедура и РС |
| `1001` | `Source` | вернуть результат |
| `1010` | `Source(position)` | изменить позицию процедуры |
| `1011` | — | завершить вызов |
| `1100` | `RegisterSelector`, `Source(size)` | изменить размер регистра |
| `1101` | `RegisterSelector`, `Destination` | получить размер регистра |
| `1110`, `1111` | — | зарезервированы, ошибка в v1 |

`0110` требует весь неизменяемый регистр процедуры и начинает её с позиции 0. `0111` начинает ту же процедуру с позиции 0 в новой РС. `1000` копирует первый источник в новый неизменяемый регистр, начинает с позиции 0 и использует вторую ссылку как вход РС.

`1001` изменяет размер регистра результата вызывающей активации под источник и копирует его. `1010` принимает целый `Value` не шире 64 бит. `1101` записывает канонический целый `Value`.

Изменение размера атомарно. Расширение дописывает нули, сокращение сохраняет префикс. Нулевой размер удаляет регистр. Удаление объекта, используемого активной процедурой, активацией или РС, запрещено.

## 11. Вычислительные операции `0100`

Коды `00000..01111` — бинарные, `10000..11111` — унарные.

| Код | Операция | Код | Операция |
|---|---|---|---|
| `00000` | `+` | `10000` | `sin` |
| `00001` | `-` | `10001` | `asin` |
| `00010` | `*` | `10010` | `cos` |
| `00011` | `/` | `10011` | `acos` |
| `00100` | остаток | `10100` | `tan` |
| `00101` | степень | `10101` | `atan` |
| `00110` | логическое И | `10110` | логическое НЕ |
| `00111` | логическое ИЛИ | `10111` | побитовое НЕ |
| `01000` | `=` | `11000` | `sinh` |
| `01001` | `!=` | `11001` | `asinh` |
| `01010` | `>` | `11010` | `cosh` |
| `01011` | `>=` | `11011` | `acosh` |
| `01100` | `<` | `11100` | `tanh` |
| `01101` | `<=` | `11101` | `atanh` |
| `01110` | побитовое И | `11110` | `ln` |
| `01111` | побитовое ИЛИ | `11111` | `lg` |

- Целые загружаются в `uint64_t`; `+`, `-`, `*`, целая степень выполняются по модулю `2^64`.
- Целые `/` и остаток беззнаковые; деление на ноль — ошибка.
- При вещественном операнде арифметика выполняется на `double`; остаток — `fmod`, степень — `pow`.
- Сравнения целых используют `int64_t`; адреса и размеры всегда беззнаковые.
- Ноль — ложь, ненулевое значение — истина; логические результаты равны 0 или 1.
- Побитовые операции принимают только целые и работают над 64 битами.
- Нефинитный результат или нарушение области определения — математическая ошибка.
- Округление соответствует IEEE-754 `round-to-nearest, ties-to-even`.

Результат кодируется как канонический `Value`, записывается в приёмник и дополняется справа нулями. Недостаточная ёмкость — ошибка без частичной записи.

## 12. Сериализация v1

```text
magic:32 = "UBCM" | version:u16_be = 1 | flags:u16_be |
record_count:u64_be | root_procedure:RegisterHandle | root_entry:NodeRef |

record := id:u64_be | flags:u8 | name:Name | bit_count:Size |
          content:bit_count | zero_padding_to_byte
```

Идентификатор записи совпадает с `id` глобального `RegisterHandle`; его старшие два бита равны нулю. Имена и идентификаторы уникальны. Флаги записи: бит 0 — неизменяемая процедура, бит 1 — регистр узлов, прочие зарезервированы.

Загрузчик проверяет версию, каноничность длин, дубликаты, границы, нулевое дополнение, выравнивание узлов, корневые и статически видимые ссылки. Динамические ссылки проверяются при использовании. Нативные указатели в файле запрещены.
