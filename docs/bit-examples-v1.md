# UBCM v1: нормативные побитовые примеры

Эти векторы являются частью спецификации UBCM v1. Реализация кодеков обязана воспроизводить их побитово.

## Обозначения

- Биты перечислены слева направо в порядке чтения VM.
- Пробелы и `|` только показывают границы полей.
- `valid_bits` — число значащих битов.
- В `hex` последний байт при необходимости дополнен нулями справа.
- Многобайтовые значения используют Big-Endian.

## `Size`

| Значение | Поля | `valid_bits` | `hex` |
|---:|---|---:|---|
| 0 | `000 | 00000000` | 11 | `00 00` |
| 1 | `000 | 00000001` | 11 | `00 20` |
| 255 | `000 | 11111111` | 11 | `1F E0` |
| 256 | `001 | 00000001 00000000` | 19 | `20 20 00` |

Например, значащая строка `Size(1)` равна `00000000001`. Пять нулей справа доводят её до двух байтов `00 20`, но не входят в поле.

## Числа

### `VarUInt(0)`

```text
bit_count  = 000 | 00000000
data       = <пусто>
bits       = 00000000000
valid_bits = 11
hex        = 00 00
```

### `VarUInt(5)`

```text
bit_count  = 000 | 00000011
data       = 101
bits       = 00000000011101
valid_bits = 14
hex        = 00 74
```

### `VarInt(-2)`

```text
bit_count  = 000 | 00000010
data       = 10
bits       = 0000000001010
valid_bits = 13
hex        = 00 50
```

### Целый `Value(5)`

```text
type       = 0
value      = VarUInt(5)
bits       = 000000000011101
valid_bits = 15
hex        = 00 3A
```

### Вещественный `Value(6.5)`

Каноническая пара — `mantissa=13`, `exponent=-1`.

```text
type                = 1
mantissa bit_count  = 000 | 00000101
mantissa data       = 01101
exponent bit_count  = 000 | 00000001
exponent data       = 1

bits       = 1 | 00000000101 | 01101 | 00000000001 | 1
           = 10000000010101101000000000011
valid_bits = 29
hex        = 80 56 80 18
```

## Имена и адреса

В примерах имя глобального регистра — битовая строка `A = 01000001`. VM не приписывает ей текстовую кодировку.

### `Name("A")`

```text
bit_count  = 000 | 00001000
data       = 01000001
bits       = 0000000100001000001
valid_bits = 19
hex        = 01 08 20
```

### Глобальный регистр `A`

```text
class      = 11
name       = Name("A")
bits       = 110000000100001000001
valid_bits = 21
hex        = C0 42 08
```

### Адрес бита 5 в глобальном регистре `A`

```text
selector   = 11 | Name("A")
offset     = 000 | 00000101
bits       = 11000000010000100000100000000101
valid_bits = 32
hex        = C0 42 08 05
```

### Прямая ссылка на адрес

```text
mode       = 10
address    = <предыдущие 32 бита>
bits       = 1011000000010000100000100000000101
valid_bits = 34
hex        = B0 10 82 01 40
```

### Трёхбитный источник по адресу

```text

bit_count  = 000 | 00000011
bits       = 101100000001000010000010000000010100000000011
valid_bits = 45

```

## Узел встроенной команды `0100`

`next0` указывает на узел 0 глобального регистра 3, `next1` — на узел по смещению 592, резолвер — на начало глобального регистра 4.

```text
TYPE | DATA = 0 | 000000000000100 = 00 04
ACTION      = 24 нулевых байта
next0       = C000000000000003 0000000000000000
next1       = C000000000000003 0000000000000250
resolver    = C000000000000004 0000000000000000
```

Полный вектор, 74 байта:

```text
0004000000000000000000000000000000000000000000000000
C0000000000000030000000000000000
C0000000000000030000000000000250
C0000000000000040000000000000000
```

## Процедура для сложения

Текущий узел уже содержит `DATA=0100`, поэтому имя команды в процедуру не входит. Фрагмент задаёт сложение непосредственных целых 5 и 3, прямой приёмник с адресом 0 в глобальном регистре `R` и переход `next1`.

```text
operation       = 00000
source 1        = 00 | VarUInt(5)
source 2        = 00 | VarUInt(3)
destination     = 10 | RegisterAddress(global, Name("R"), 0)
branch          = 1

bits       = 00000000000000001110100000000000101110110000000100001010010000000000001
valid_bits = 71
hex        = 00 00 E8 00 BB 01 0A 40 02
```

После успешного шага курсор продвинут на 71 бит, в приёмник записан канонический `Value(8)`, а текущим узлом становится `next1`.

## Отрицательные векторы

Декодер обязан отклонять:

- `Size(1)`, записанный двумя байтами значения;
- `VarUInt(5)` с шириной 4 и данными `0101`;
- `VarInt(-2)` с шириной 8 и данными `11111110`;
- ненулевые дополняющие или зарезервированные биты;
- `NodeRef` за границей регистра либо с неверным выравниванием;
- встроенный узел с ненулевым `ACTION` или старшими 11 битами `DATA`;
- узел размером не 592 бита или активацию размером не 744 бита;
- непосредственную ссылку в позиции `Destination`;
- косвенность глубже 64;
- фрагмент `0100`, содержащий имя команды перед пятибитным кодом операции.
