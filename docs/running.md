# Запуск UBCM

Сборка и пример `5 + 3`:

```sh
cmake -S . -B build
cmake --build build -j2
build/ubcm_demo build/demo
build/ubcm build/demo/procedure.ubcp build/demo/network.ubcm --dump 2
```

Результат — остановка после двух шагов и содержимое глобального регистра 2:
`00000000010010000000000000000000` (канонический `Value(8)` с нулевым хвостом).
Генератор примера записывает три файла в указанную папку; при повторном запуске
перезаписывает их.

Можно использовать единый контейнер:

```sh
build/ubcm build/demo/combined.ubcm --steps 1000 --depth 64 --dump 2
ctest --test-dir build --output-on-failure
```

CLI принимает один контейнер или два файла: процедуру и контейнер РС.
Флаги `--steps` и `--depth` задают ограничения, `--dump ID` печатает биты
глобального регистра после исполнения. Коды выхода: 0 — завершение, 1 — ошибка,
2 — исчерпан бюджет шагов. `--help` показывает синтаксис, `--version` — версию.

## API

`VirtualMachine::run(max_steps, max_activation_depth)` выполняет программу до
завершения или исчерпания числа шагов. По умолчанию: 1 000 000 шагов и 256 активаций.

Результат содержит число выполненных шагов и признак `halted`. Если бюджет шагов
исчерпан, состояние сохраняется и можно снова вызвать `run()`. Бюджет 0 ничего
не выполняет. После завершения повторный `run()` возвращает 0 шагов и `halted=true`.

Ошибочная команда, включая превышение глубины вызовов, не применяется. Уже
выполненные команды сохраняются. `step(max_activation_depth)` позволяет выполнять
программу по одной команде с тем же ограничением глубины.
