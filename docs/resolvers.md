# РС-резолверы

Резолвер получает биты имени как тело неизменяемой процедуры и контекст
активации, для которой разрешается имя. VM выполняет обычные узлы выбранной РС.
Временная активация резолвера ссылается на выбранную: foreign-глубина 1
позволяет читать её локальные данные, 2 — данные её предшественника.

Выбор сети:

- локальные имена: `ActivationRecord::local_resolver`;
- сверхлокальные: `superlocal_resolver` текущего узла выбранной активации;
- глобальные: сеть, заданная через `set_global_resolver(entry)`.

При нулевой ссылке используются явно переданные таблицы `NameResolver`.
Настроенная РС имеет приоритет: при её ошибке отката к таблице нет.
Пустое локальное имя зарезервировано для регистра результата и не запускает РС.

## Возврат адреса

`RESOLVE_RETURN` имеет код `1110` и два аргумента `Source`:
номер глобального регистра и смещение в битах. Бита ветвления нет.
Оба значения беззнаковые; номер помещается в 62 бита существующего формата
handle, смещение — в 64 бита.

Команда возвращает адрес и завершает весь запуск резолвера, включая вложенные
обычные вызовы. Вне резолвера она является ошибкой. `1001` запрещена.
Завершение через `1011` без `RESOLVE_RETURN` — ошибка.
При ложном условном префиксе `RESOLVE_RETURN` потребляет аргументы и снимает
префикс, но не возвращает адрес и не меняет текущий узел.

Адрес может обозначать ещё не созданный регистр, например для `1100`.
Границы чтения/записи проверяет использующая адрес команда.

## Read-only режим

Регистры вызывающей VM защищены от записи. Команды `COPY`, вычисление с
приёмником, изменение размера, получение размера с записью в приёмник и
`1001` запрещены, даже если записывали бы прежнее значение. Подавленная условием
команда не выполняет запись и допустима.

VM создаёт приватные процедуру имени, активации и ячейки состояния сети.
Изменение их курсоров и обычные вызовы нужны для интерпретации РС и допускаются.
Попытка изменить курсор или состояние вызывающей активации префиксом
завершается ошибкой защиты. Запись данных запрещена и во временные регистры.

Исполнение идёт на копии банка: после успеха переносится только адрес.
Временные регистры и изменения счётчика ID отбрасываются. Защита записей
проверяется отдельно: наличие копии не делает попытку записи допустимой.
Ошибка резолвера отменяет всю использующую его команду.

На запрос отведено 10 000 шагов, общих с вложенными запросами, и до 32 уровней
вложенности резолверов. Обычные вызовы внутри резолвера ограничены 256
дополнительными активациями. Исчерпание лимита — ошибка ресурсов.

## API и пример

`vm.resolve_name(scope, name, depth)` проверяет имя отдельно: глубина 0
выбирает текущую активацию, 1 — предыдущую. Запрос читает актуальную цепочку
из регистров и не изменяет состояние VM.

```sh
build/ubcm_demo build/demo
build/ubcm build/demo/resolver.ubcm --global-resolver 4:0 --dump 2
```

В примере резолвер возвращает адрес регистра 2 через обычный узел вызова
и `RESOLVE_RETURN`. Он одинаково обрабатывает все имена. Реальный резолвер
может разбирать биты имени командами выбора.
